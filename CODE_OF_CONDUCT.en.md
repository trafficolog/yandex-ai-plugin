# Code of Conduct

[Русский](CODE_OF_CONDUCT.md) · [**English**](CODE_OF_CONDUCT.en.md)

This code defines the baseline for interaction in issues, pull requests, reviews, discussions, and other community spaces of this repository.

## 1. Expected behavior

Participants should discuss ideas and changes respectfully, critique technical decisions rather than people, provide verifiable reasoning, and distinguish facts from assumptions. Review may be rigorous, but it must not become harassment, threats, discrimination, abuse, or publication of another person's private data.

## 2. Technical integrity

For safety-sensitive changes, contributors must describe evidence limitations, test results, and review status truthfully. An AI audit, self-review, or green CI must not be presented as independent review when that review did not occur. Credentials, access tokens, and other secrets must not be posted in issues or pull requests.

## 3. Scope

This code applies to interaction related to this repository and its official GitHub surfaces. It does not establish rules for unrelated external communities or services.

## 4. Reporting problems

For conduct violations, use available GitHub moderation/reporting mechanisms and maintainer contact surfaces explicitly exposed by the repository. Do not invent or assume private contact coordinates or response SLAs.

If a report concerns a vulnerability, secret exposure, approval-gate bypass, or other security-sensitive behavior, follow [`SECURITY.en.md`](SECURITY.en.md) and avoid posting exploitation details publicly unless necessary.

## 5. Enforcement

Maintainers may hide or close abusive/off-topic discussion, request wording changes, restrict participation, or use other GitHub moderation controls. Actions should be proportionate to the behavior and context and, where practical, preserve the technical history of the discussion.
