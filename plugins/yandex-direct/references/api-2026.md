# Yandex Direct API facts

Verified: 2026-09-04

Use this file as a compact factual baseline. For fields or policy limits that may change, verify the linked official documentation before making a write request.

## API version and environments

- Production JSON API uses `https://api.direct.yandex.com/json/v501/{service}`.
- Sandbox JSON API uses the separately documented `https://api-sandbox.direct.yandex.com/json/v5/{service}` path contract.
- Do not derive the sandbox endpoint by hostname substitution while preserving `/v501/`.

## Supported v5 service inventory

The bundled helper accepts the union of service endpoints explicitly documented by the current official API reference and current official API Units table:

`adextensions`, `adgroups`, `adimages`, `ads`, `advideos`, `agencyclients`, `audiencetargets`, `bids`, `businesses`, `bidmodifiers`, `campaigns`, `changes`, `clients`, `creatives`, `dictionaries`, `dynamictextadtargets`, `feeds`, `keywordbids`, `keywords`, `keywordsresearch`, `leads`, `negativekeywordsharedsets`, `retargetinglists`, `sitelinks`, `smartadtargets`, `strategies`, `turbopages`, `vcards`.

The reference index and Units table expose slightly different service surfaces. The strict helper allowlist therefore uses their documented union rather than treating either page alone as exhaustive. Unknown names, query/path fragments, and whitespace-decorated service values are rejected before URL construction.

## Authentication and agency accounts

Send `Authorization: Bearer <OAuth token>`. The bundled CLI reads the token only from `YANDEX_DIRECT_TOKEN`; do not place OAuth tokens in command-line arguments, skill text, git, generated reports, or chat output. For an agency managing a client, use `Client-Login` when the API method supports it.

## Response transport metadata

The Direct-local HTTP adapter exposes selected documented response headers separately from the API payload:

- `RequestId` → `request_id`;
- `Units` → `units`;
- `Units-Used-Login` → `units_used_login`.

Other response headers are not copied into the agent-facing transport object by default.

## Reports

- Reports endpoint: `https://api.direct.yandex.com/json/v501/reports`.
- Reports are TSV.
- `processingMode` may be `online`, `offline`, or `auto`.
- HTTP 201 means queued; HTTP 202 means still generating; wait for the response header `retryIn` and resend the **same request parameters**.
- `returnMoneyInMicros: false` returns report money in account currency with two decimal places. Without it, report money is in millionths.
- Monetary values in report **filters** still use millionths regardless of `returnMoneyInMicros`.

Official docs:
- https://yandex.ru/dev/direct/doc/ru/reports
- https://yandex.ru/dev/direct/doc/reports/mode.html

- https://yandex.ru/dev/direct/doc/ru/money

## Keywords and autotargeting

The `Keywords` service operates on both keywords and autotargeting. Autotargeting is represented by the special keyword value `---autotargeting`. Do not assume autotargeting is equivalent to an ordinary broad-match keyword; audit and report it separately via `CriterionType=AUTOTARGETING` where relevant.

Official docs:
- https://yandex.ru/dev/direct/doc/ru/keywords/keywords
- https://yandex.ru/dev/direct/doc/ru/best-practice/auto-targeting

## Negative phrases

Negative phrases can be set at campaign/group level, via shared negative sets, and inside a keyword. `NegativeKeywordSharedSets` supports add/update/delete/get. Shared sets are useful for governance, but cross-negative logic must be based on intended query routing rather than blindly subtracting every sibling group.

Official docs:
- https://yandex.ru/dev/direct/doc/ru/objects/negative-keywords
- https://yandex.ru/dev/direct/doc/ru/negativekeywordsharedsets/negativekeywordsharedsets

## IDs

Yandex object identifiers can exceed JavaScript's safe integer range in integrations. Preserve IDs as decimal strings in JavaScript/JSON transformations when there is any risk of 64-bit values being rounded. Python integers are arbitrary precision.
