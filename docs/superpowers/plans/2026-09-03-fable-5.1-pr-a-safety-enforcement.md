# FABLE 5.1 PR A — Safety Enforcement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bind every consequential Direct, Metrika, and Webmaster execution to the exact secret-free operation preview approved by the user, while preserving read-only behavior and independent plugin installability.

**Architecture:** Each write-capable service plugin receives a tiny service-local `_approval.py` adapter with the same behavioral contract but no shared runtime dependency. Consequential transport boundaries build a canonical `yandex-ai-approval/v1` envelope, emit a full SHA-256 `preview_id` during preview, and require `--execute --approve <preview_id>` before transport. Specialized Webmaster request builders remain pure; approval is enforced at the final `yw_api.py` transport boundary. Metrika import approval additionally binds the SHA-256 of uploaded file bytes.

**Tech Stack:** Python 3.10+, stdlib (`hashlib`, `json`, `argparse`, `pathlib`, `unittest`), existing plugin-local helper architecture.

**Spec:** `docs/superpowers/specs/2026-09-03-fable-5.1-remediation-design.md`

## Global Constraints

- Safety lifecycle remains `read → analyze → preview → explicit approval → write → verify`.
- A helper enforces exact-operation integrity; it does not claim cryptographic proof that a human approved in a previous conversation turn.
- Missing/mismatched approval errors must not reveal the expected digest.
- Canonical approval JSON uses sorted keys, compact separators, UTF-8, and `ensure_ascii=False`.
- Authorization tokens/API keys are excluded from canonical approval data.
- Direct approval binds environment, service/URL, Direct method, `Client-Login`, and body.
- Metrika approval binds method, full URL/query, counter/operation identifiers, body, and uploaded file SHA-256 where applicable.
- Webmaster approval binds API version, method, full URL/query, host/site/operation identifiers, and body.
- Read-only operations do not require approval.
- No root shared runtime package is introduced; each plugin remains independently installable.
- Direct, Metrika, and Webmaster move to `2.0.0` because `--execute` without `--approve` becomes invalid.
- No 2.0.0 tags/releases are published until PR A, PR B, and PR C are merged and green.

Each exposes the same small interface:

```python
def preview_id(envelope: Mapping[str, Any]) -> str: ...
def require_approval(envelope: Mapping[str, Any], supplied: str | None) -> str: ...
```

`require_approval()` returns the expected digest on success and raises `ValueError("execution requires approval of the exact preview; generate and show a fresh preview first")` on missing/mismatch. It never includes the expected digest in the exception text.

```python
from __future__ import annotations

import hashlib
import json
from typing import Any, Mapping

ERROR = "execution requires approval of the exact preview; generate and show a fresh preview first"


def _canonical_json(envelope: Mapping[str, Any]) -> str:
    return json.dumps(envelope, sort_keys=True, separators=(",", ":"), ensure_ascii=False)


def preview_id(envelope: Mapping[str, Any]) -> str:
    return hashlib.sha256(_canonical_json(envelope).encode("utf-8")).hexdigest()


def require_approval(envelope: Mapping[str, Any], supplied: str | None) -> str:
    expected = preview_id(envelope)
    if not supplied or supplied != expected:
        raise ValueError(ERROR)
    return expected
```

```python
def sha256_file(path: Path) -> str:
    digest = hashlib.sha256()
    with Path(path).open("rb") as handle:
        for chunk in iter(lambda: handle.read(1024 * 1024), b""):
            digest.update(chunk)
    return digest.hexdigest()
```
