# FABLE 5.1 Review 5 Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the residual fifth-review gaps with test-first Direct Reports hardening, honest SEO semantic tests, stronger Direct contract/freshness traceability, and repository/docs cleanup, then publish patch releases through the existing immutable release discipline.

**Architecture:** Keep HTTP ownership service-local. Harden `yd_report.py` in place rather than introducing a shared transport package; preserve Reports-specific polling as a separate read-only workflow. Treat contract/docs changes as traceability around already-implemented behavior, and change SEO production code only if corrected tests expose a genuine defect.

**Tech Stack:** Python 3.10/3.13, `unittest`, GitHub Actions, JSON contract matrices/manifests, Markdown RU/EN documentation.

**Spec:** `docs/superpowers/specs/2026-09-04-fable-5.1-review5-remediation-design.md`

## Global Constraints
- Existing immutable tags/releases must never be retargeted or rewritten.
- Direct OAuth CLI input is environment-only through `YANDEX_DIRECT_TOKEN`.
- Direct Reports HTTP error reads are capped at 4096 bytes and decoded with `errors="replace"`.
- Reports retains 201/202 polling and at most one automatic HTTP 500 retry; do not add generic POST retries elsewhere.
- No root/shared HTTP package.
- SEO remains `1.1.2` unless corrected RED tests require production behavior changes.
- Direct bumps to `2.0.1`; repository maintenance release is `1.0.3`.
- Every executable behavior change follows observed RED → minimal GREEN → regression GREEN.
