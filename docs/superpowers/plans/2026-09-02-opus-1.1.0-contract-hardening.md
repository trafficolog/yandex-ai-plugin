# OPUS 1.1.0 Contract Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining verified OPUS review findings without regressing the 1.0.1 safety and semantics baseline.

**Architecture:** Keep each service plugin as the owner of its external API contract and deterministic normalization. Cross-service SEO/Marketing code may propagate limitations but must not invent transport behavior, credentials, quotas, or source authority. Repository controls remain offline and deterministic: freshness is date-policy validation and `docs/CONTRACT_MATRIX.json` is path-based executable traceability.

**Tech Stack:** Python 3 standard library, `unittest`, JSON plugin manifests, Markdown skill/reference documentation, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-02-opus-1.1.0-contract-hardening-design.md`

## Global Constraints

- Preserve independent SemVer: Direct 1.0.1, Metrika 1.0.1, Webmaster 1.0.2, Wordstat 1.0.2, Search 1.0.2, SEO 1.0.1, Marketing 1.1.0.
- Preserve the 1.0.1 regression baseline: Direct safe-by-default mutation gate, Metrika attribution omission, Webmaster feeds batch body, SEO context/geo semantics, Marketing money-context, Search absolute rank and tracking URL identity.
- No new live-mutation owner. Global invariant remains `read -> analyze -> preview -> explicit approval -> write -> verify`.
- Cross-service plugins remain transport-free and credential-free.
- No autonomous Webmaster PRO polling or scheduling.
- Search windows crossing the 250-result ceiling are rejected; no implicit partial-final-page behavior.
- Wordstat weekly/monthly operator restriction is repository compatibility policy, not a documented Yandex prohibition.
- Freshness CI performs no external web requests. `MAX_REFERENCE_AGE_DAYS = 90`.
