# OPUS 1.1.1 Follow-up Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship OPUS 1.1.1 with diff-aware freshness validation, scheduled strict freshness reporting, explicit blocker traceability, Metrika Direct-expense guard hardening, Webmaster archive contract verification, and synchronized RU/EN release documentation.

**Architecture:** Keep service ownership unchanged. Repository validation becomes changed-reference-aware while a separate scheduled workflow owns global freshness pressure. Contract matrix remains a traceability index; service runtime changes are limited to the Metrika label guard, while Webmaster receives contract/reference pinning for already-correct `state` behavior.

**Tech Stack:** Python 3.13 stdlib, unittest, GitHub Actions, JSON/Markdown plugin manifests.

**Spec:** `docs/superpowers/specs/2026-09-02-opus-1.1.1-follow-up-fix-design.md`

## Global Constraints

- Keep seven-plugin architecture unchanged.
- Do not introduce cross-service HTTP clients or credentials.
- Preserve `read → analyze → preview → explicit approval → write → verify`.
- Keep `MAX_REFERENCE_AGE_DAYS = 90`.
- Only Metrika and Webmaster plugin SemVer may change in this release.
- RU unsuffixed docs remain canonical; `.en.md` mirrors stay release-marker compatible.
