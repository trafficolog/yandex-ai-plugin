# OPUS 1.1.2 Residual Audit Hardening Amendment

**Status:** normative follow-up to final Opus 5 residual findings  
**Date:** 2026-09-03  
**Issue:** #32

## Purpose

Close the genuine remaining audit tail without reopening findings already resolved by OPUS 1.1.1 or weakening the independent-plugin architecture.

## Already resolved findings

The following findings require no new runtime change in OPUS 1.1.2:

- **N3:** `CONTRACT_MATRIX.json` is explicitly a traceability index, not semantic proof; `PLUGIN_STANDARD` states that a listed test file does not prove that the test asserts the invariant.
- **N5:** `.agents` authentication metadata remains `ON_USE` for transport-free cross-service plugins because the marketplace schema requires an authentication policy and supports `ON_INSTALL` / `ON_USE`; `ON_USE` is deferred metadata, not a credential claim.
- **N6:** Yandex Webmaster archive status is independently verified as response field `state` with `IN_PROGRESS` / `DONE` / `FAILED` plus `download_url` for the completed archive; runtime and contract-matrix traceability already match that contract.
- **N8:** the Marketing design itself now normatively distinguishes the nine locally implemented finding types from deferred and external-only vocabulary.

## N4 — Metrika expense provenance hardening

Yandex Metrika `1.0.3` closes the residual gap where an expense CSV could omit `UTMSource` / `UTMMedium` and use an ambiguous human provider label.

The import helper classifies CSV source evidence as:

- `DIRECT` — proven Direct provenance, including Direct-like UTM evidence and official `TrafficSourceDetail=yandex_direct_star`;
- `NON_DIRECT` — explicit evidence identifies another source;
- `UNVERIFIED` — source evidence is insufficient to rule Direct out, for example generic `TrafficSource=ad` without a source detail.

`DIRECT` raises `DIRECT_DUPLICATION_RISK`. `UNVERIFIED` raises `DIRECT_SOURCE_UNVERIFIED`. Both require the existing explicit `--allow-direct-risk` override after review. A provider label such as `MyDirect` is still not declared Direct provenance by substring alone; the fail-closed decision comes from insufficient CSV evidence, not from inventing label semantics.

## N7 — shared runtime promotion gate

The duplicated service-local `_http.py` helpers are not promoted to root `packages/` in this release.

The original reuse rule is amended as follows:

1. repeated responsibility in at least two plugins is necessary;
2. a stable common interface is necessary;
3. **an independently installable distribution contract is also necessary**.

A shared runtime package may be introduced only when every independently installed plugin can receive the dependency through a supported versioned dependency mechanism or a reproducible build/vendor step. Hidden imports from the monorepo root are forbidden because they would make a plugin work in the repository while failing after standalone installation.

Until that distribution boundary exists, small service-local adapters may remain duplicated. Independent installability takes precedence over formal DRY.
