# OPUS 1.1.3 — Phase 7 audit hardening normative amendment

Date: 2026-09-03
Status: normative patch amendment
Parent: `2026-09-02-phase-7-topical-architecture-semantic-cocoons-design.md`

This amendment closes the P1–P8 findings from the post-Phase-7 Opus 5 audit against the current renamed repository. Where the audit snapshot references the former repository identity, current GitHub state is authoritative.

## 1. Page-boundary evidence safety

For `CREATE`, `MERGE`, `SPLIT`, `REDIRECT`, `SECTION_ONLY`, `BRIDGE`, and `NO_PAGE`:

- an empirical `OBSERVED` or `DERIVED` claim MUST contain at least one Search-owned reason code: `SERP_OVERLAP` or `SERP_BRIDGE_RISK`;
- Wordstat association/frequency evidence cannot by itself justify an empirical boundary decision;
- `coverage.search=PARTIAL` MUST emit `SERP_VALIDATION_PARTIAL`;
- `coverage.search=MISSING` retains the existing `SERP_VALIDATION_MISSING` rule and boundary decisions remain `HYPOTHESIS`;
- empirical `MERGE` and `REDIRECT` additionally require existing-page evidence through `WEBMASTER_EXISTING_URL` or `METRIKA_LANDING_TRAFFIC`.

These are validation rules, not instructions to execute redirects or page migrations. Recommendation state remains preview-only.

## 2. Evidence classes

`METHODOLOGY` is a first-class kind in the canonical SEO Evidence Bundle alongside `OBSERVED`, `DERIVED`, and `HYPOTHESIS`.

Methodology evidence is qualitative provenance. It MUST NOT carry a quantitative `metric` or `value`; a quantitative conclusion must instead be supported by observed/derived source evidence. This prevents methodology from being relabeled merely to pass the bundle validator.

## 3. Publisher repository identity

The canonical GitHub repository identity is `trafficolog/yandex-ai-plugins-skills`.
Every literal `github.repository == '...'` guard in repository publish workflows MUST use that identity. Tests scan all publish workflows rather than asserting isolated substrings in one workflow. Historical release target SHAs/tags remain immutable; correcting a workflow guard never retargets a historical release.

## 4. Internal-link audit semantics

The audit distinguishes directed inbound connectivity from generic participation in a link:

- `ORPHAN_PAGE` means a non-root page has zero valid inbound links;
- outgoing links do not rescue a page from orphan status;
- an explicit `ROOT` node is exempt;
- a parentless `BRIDGE` is not exempt and is orphaned when it has no inbound link;
- duplicate valid `(source,target)` links are retained in observed counts and emit `DUPLICATE_LINK` with occurrence count;
- a missing semantic edge with relation `BRIDGE` additionally emits `BROKEN_SEMANTIC_BRIDGE`;
- graph cycles remain legal unless another concrete UX/navigation rule is violated.

## 5. Cross-service query normalization

Wordstat topic-map normalization MUST use Unicode NFKC before whitespace normalization and `casefold()`, matching SEO/Marketing query-join semantics. Compatibility/full-width forms must join to the same normalized key across service boundaries.

This patch does not promote normalization into `packages/`: the independent-plugin distribution/installability gate from OPUS 1.1.2 still applies.

## 6. Artifact stage state

`seo-topical-architecture/v1` distinguishes **not evaluated** from **evaluated and empty**:

- base `link_plan`, `audits`, `consistency.navigation_conflicts`, and `consistency.parity_checks` are `null` until their stage runs;
- `attach_link_plan()` sets a validated list, including `[]` when the evaluated result is empty;
- `attach_audit()` materializes/extends the audit list;
- `attach_consistency_results()` materializes validated navigation/parity lists.

Consumers must not interpret `null` as “no findings/no links”.

## 7. Search cluster ingress and source limitations

SEO Topical Architecture only accepts normalized Search-owned cluster records with non-empty unique `cluster_id`, non-empty `queries`, positive integer `min_shared_urls`, boolean `bridge_risk`, and optional list-typed `limitations`.
Malformed cluster evidence is rejected instead of copied through. Any `bridge_risk=true` propagates `SEARCH_BRIDGE_RISK` into architecture limitations. Cluster limitations propagate downstream.

The builder also accepts `source_artifacts`; a supplied `wordstat-topic-map/v1` artifact propagates its list-typed limitations (including `WORDSTAT_ASSOCIATIONS_CAPPED`) automatically. This is provenance propagation, not demand aggregation.

## 8. Spec/implementation reconciliation

For §14/§15/§17 of the Phase 7 design:

- duplicate-link, orphan, structural, semantic-link and bridge checks above are implemented deterministically;
- navigation conflicts/parity checks become explicit attachable evaluation stages rather than fabricated empty outputs;
- source limitation propagation is executable rather than caller-copy convention;
- semantic cycles are still intentionally permitted absent a concrete UX/navigation failure.
