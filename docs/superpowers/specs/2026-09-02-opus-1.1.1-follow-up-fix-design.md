# OPUS 1.1.1 Follow-up Fix Design

**Status:** approved from final Opus 5 review + implementation scope decision  
**Date:** 2026-09-02  
**Issue:** #20

## Goal

Close the remaining actionable final-review findings without widening the architecture boundary or creating synchronized plugin version churn.

## Release/version boundary

Repository milestone: `OPUS 1.1.1`, tag `opus-1.1.1`.

Plugin versions changed by this fix:

- `yandex-metrika`: `1.0.1` → `1.0.2` because expense-import duplicate-risk behavior is hardened and documented.
- `yandex-webmaster`: `1.0.2` → `1.0.3` because the archive lifecycle public contract is explicitly verified, traced and regression-pinned.

Unchanged: Direct `1.0.1`, Wordstat `1.0.2`, Search `1.0.2`, SEO `1.0.1`, Marketing `1.1.0`.

## N1 — reference freshness without time-bomb CI

`validate_reference_freshness` continues to define the strict 90-day rule. Repository validation gains scope:

- malformed/missing/future verification markers remain errors whenever a freshness-controlled reference is validated;
- staleness age is a hard error in ordinary PR/push validation only when that exact reference path is in the changed-file set;
- unchanged stale references do not break unrelated PRs;
- a scheduled strict workflow checks every freshness-controlled reference and opens/updates a GitHub issue when stale references exist;
- manual strict execution is available through a dedicated checker.

The repository validator accepts a changed-files input; CI computes the changed set from the PR base or push `before` SHA.

## N2/N3 — contract matrix semantics

Add explicit traceability for the Direct-expense duplication guard and Webmaster indexing archive lifecycle. Review-blocker coverage must be visible in the matrix.

`CONTRACT_MATRIX.json` is explicitly a **traceability index**, not semantic proof. Validation establishes structure, paths, declared tests and selected freshness metadata. It does not prove that a listed test actually asserts the invariant or that an eval has been executed against a model.

## N4 — Metrika expense source labels

Retain content-based `UTMSource`/`UTMMedium` detection as the stronger second layer. Expand label detection conservatively to reject common tokenized Direct labels such as `Yandex Direct RU`, `direct_ads` and Russian equivalents without treating arbitrary concatenations such as `MyDirect` as proven Direct provenance.

## N5 — cross-service marketplace authentication metadata

Do not introduce `NONE`. The current Codex marketplace specification requires `policy.authentication` and supports only `ON_INSTALL` / `ON_USE`. Keep cross-service SEO/Marketing at `ON_USE` and document that this is schema-compatible deferred-auth metadata; those plugins still have no local credential or transport surface.

## N6 — Webmaster archive field

Official Yandex Webmaster documentation verified on 2026-09-02 documents:

- `GET /v4/user/{user-id}/hosts/{host-id}/indexing/archive/{task-id}`;
- response field `state`;
- values `IN_PROGRESS`, `DONE`, `FAILED`;
- `download_url` when `state == DONE`.

Current runtime code is correct. Add explicit reference wording and contract-matrix traceability to `yw_indexing.py` + `test_yw_indexing.py`.

## N8 — Marketing taxonomy spec reconciliation

Amend the approved Marketing design to distinguish the broad design vocabulary from the **implemented executable taxonomy**. The current implementation has nine locally produced finding types plus explicit deferred/unknown handling; the spec must say so rather than implying all originally enumerated classes are executable.

## Out of scope

- N7: promoting duplicated `_http.py` helpers to `packages/`. This is a separate shared-interface/refactor decision.
- building a live model eval runner. Evals remain structurally validated offline fixtures; documentation must not imply otherwise.
